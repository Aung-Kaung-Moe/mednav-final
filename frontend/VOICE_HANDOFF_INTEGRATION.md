# MEDNAV voice handoff integration

The prior dashboard Voice response card was removed. The assistant in `src/voice/` comes from `MEDNAV_Voice_Handoff`: its 13 command groups and guided questionnaire remain, while recognition now uses the local `Systran/faster-whisper-tiny.en` server and speech output uses Piper. The assistant stays mounted across pages. Its Synthetic demo adapter uses the currently selected Crew A/B/C, current inventory, existing trend records and scripted investigation fixtures. A confirmed voice check-in updates the same in-memory crew profile as the form; the investigation page receives its result. Manual investigation also publishes its current scripted response for the assistant's recommendation command.

Run the Vite app with `npm run dev` and allow microphone access when the browser asks. MEDNAV starts listening when the app loads, including while its panel is closed. Say **Hey MEDNAV** to open the panel and hear a greeting, **Health Check** to begin the questionnaire, or **Stop** to release the microphone. A new command or check-in answer can interrupt a spoken reply. Select **VOICE AI** to start a new listening session after stopping. The panel has no microphone toggle; its text field can test commands without a microphone. A voice check-in asks for explicit confirmation before saving. `mode=api` is hidden until the backend contract is reconciled. The original Health Check-In recorder remains available as a separate optional control.

Run `python frontend/voice_server.py` from the project root to serve the tiny Faster-Whisper model on port 8002. The assistant captures short WAV segments after microphone permission and posts them to Vite's local `/mednav-voice/transcribe?segment_mode=true` route, roughly every 2.4 seconds, or every 0.8 seconds while speaking to allow interruption. This dedicated route keeps the assistant separate from the main API's voice endpoint on port 8000. Live segments use voice activity filtering, narrow wake/Stop hints, confidence checks, and a repetition filter so a word loop such as repeated “BPM” is discarded before it reaches the UI. Piper must be running locally on port 5000 with `en_US-lessac-medium`; the existing Vite `/piper` proxy is retained. The Piper HTTP server labels WAV bytes as HTML, so the speaker checks the RIFF header and marks the blob as WAV. Without Piper, responses remain visible as text. The older Vosk package and script have been removed; the unused model archive remains locally ignored by Git because automated deletion was rejected.

Verification: `npm run test:voice`, `npm run build`, and `npm test`. Tests cover commands and parsing, typed voice navigation and confirmed save, fixture synchronization, the tiny model readiness endpoint, segmented wake transcription, and the spoken Stop releasing the microphone. Acoustic recognition and speaker output require manual testing with a real microphone and speakers. The main app remains an in-memory synthetic demonstration; voice does not add durable persistence or clinical advice.

The microphone recognizer loads separately from the dashboard bundle. Piper speaks the assistant's replies when the local server and browser audio output are available.
